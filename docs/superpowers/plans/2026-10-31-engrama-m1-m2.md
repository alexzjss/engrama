# Engrama M1+M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the living core of Engrama (M1: headless, tested simulation of needs, traits, stages, SNN, behavior, learning, memory, persistence) and its body and voice (M2: pygame window, procedural sprites, chat via local Ollama, SNN view, rest mode, PT/EN UI).

**Architecture:** One process. A simulation object is the single writer of creature state and memory and ticks at 1 Hz (sim time). UI, the language worker thread and the resource guard only post `Event`s to a thread-safe bus, and the simulation consumes them each tick. The UI renders from a read-only snapshot. The SNN (numpy LIF, reward-modulated STDP) turns stimuli into per-behavior firing rates plus arousal and valence. Those feed a utility-based behavior selector biased by contextual bandits. The LLM (Ollama, managed subprocess with all data on drive E:) is used only for language.

**Tech Stack:** Python 3.13, pygame-ce, numpy, psutil, sqlite3 (stdlib), pytest. HTTP is plain `urllib` (no requests).

**Spec:** `docs/superpowers/specs/2026-10-31-engrama-design.md` (read sections 3, 4, 5, 6, 9 before any task). The throwaway prototype in `spike/` is a reference for working snippets (SNN loop, sprite mirroring, chiptune synth, Ollama calls, `<think>` stripping, few-shot persona). Do not import it.

## Global Constraints

- **Python and venv:** Python 3.13. The venv is at `<repo>/.venv`, created with `py -3.13 -m venv .venv`. Run tests with `.venv/Scripts/python -m pytest`.
- **Dependencies:** `pygame-ce`, `numpy`, `psutil`, `pytest` (dev) and nothing else. Declare them in `pyproject.toml` (package `engrama`, `requires-python = ">=3.13"`).
- **Nothing on drive C:**
  - All app data lives under `Config.data_dir`, which defaults to `<repo>/data` and must be gitignored.
  - Ollama: the executable defaults to `E:\Ollama\ollama.exe`. The server is started with env `USERPROFILE=E:\Ollama\home`, `HOME=E:\Ollama\home`, `OLLAMA_MODELS=E:\Ollama\models`.
  - Never launch `ollama app.exe`.
- **Offline:** no network access except `http://localhost:11434` (Ollama).
- **No raw numbers to the LLM:** needs and traits must never appear as digits in prompts. Replies containing digits or assistant phrases ("como posso ajudar", "how can I help") are rejected.
- **Initial traits:** curiosidade 50, sociabilidade 40, paciencia 70, independencia 30, criatividade 50. Trait keys are ASCII, without accents.
- **Needs:** keys are `fome, sono, tedio, carinho, curiosidade, apoio`. The scale is 0–100, where high means a strong urge. `empolgacao` is a mood value, not a need.
- **Stages:** `egg, baby, child, adult, perfect, final`.
- **Languages:** creature speech follows the user's language (pt/en). The UI uses i18n strings for pt and en, defaults to the system locale, and can be switched in settings.
- **Resource targets** (measured and reported, not gates): with no LLM loaded the core uses ≤150 MB RAM and ≤2% average CPU, renders at ≤20 FPS, and at 5 FPS when unfocused.
- **Commits:** conventional messages, **no `Co-Authored-By` or any Claude attribution line**. Work on branch `m1-m2`. The PR merges into `main` at the end, and is not pushed until the user's final step.
- **Tests:** headless. Pygame tests set `SDL_VIDEODRIVER=dummy` and `SDL_AUDIODRIVER=dummy`. Tests must never touch the real `data/` dir; use `tmp_path`. Tests must never require a running Ollama: inject fake HTTP functions instead.

## Review Focus

1. **Ollama problems:** the case is Ollama missing, not running, or dying mid-chat. Expected: the creature keeps living, chat answers with babble, and the HUD shows a clear state with no crash or freeze. Tests: Task 9 `test_client_offline_*`, Task 10 `test_worker_falls_back_when_offline`.
2. **Time going wrong:** the case is a very long offline gap (months) or the system clock going backwards. Expected: needs are capped at `OFFLINE_NEED_CAP`, no sickness or death from offline time, and no crash. Test: Task 8 `test_offline_catchup_long_gap_and_backwards_clock`.
3. **Broken saves:** the case is a corrupted or half-written save (power loss). Expected: load the newest valid backup, and never silently start a new egg over an existing creature. Test: Task 7 `test_corrupt_state_loads_backup`.
4. **Odd chat input:** the cases are empty, whitespace-only, very long (5000 chars), emoji-only, or mixed-language messages. Expected: empty and whitespace-only messages are ignored, long ones are truncated to 500 chars, and nothing crashes. Test: Task 10 `test_odd_inputs`.
5. **Spam:** the case is clicking or feeding 200 times in a row. Expected: needs stay in 0..100, the SNN does not saturate (hidden rate < 200 Hz), food refusal still works, and there is no runaway reward. Tests: Task 2 `test_needs_clamped_under_spam`, Task 8 `test_spam_feed_and_pet`.

### Task 4: Stimuli and SNN

**Files:**
- Create: `engrama/brain/stimuli.py`, `engrama/brain/snn.py`, `tests/brain/test_snn.py`

**Interfaces:**
- Consumes: `BEHAVIORS` from Task 5 is not imported. `snn.py` defines `N_BEHAVIORS = 7` and Task 5's catalog order must match:
  `("idle","wander","play_alone","sleep","ask_attention","explore","show_something")`.
- Produces:
  - `INPUTS = ("click","chat","chat_pos","chat_neg","feed","hunger","sleepy","boredom","lonely","curious","night","novelty","user_active","noise")`. That is 14 inputs.
  - `encode(levels: dict[str,float]) -> np.ndarray`: shape (14,), values clipped to 0..1, missing keys give 0, and `noise` defaults to 0.15.
  - `SNN(seed: int, hidden: int = 32)` contains:
    - **Populations:**
      - 14 inputs (Poisson, max prob 0.2/step).
      - A hidden recurrent excitatory layer of size `hidden`, plus `hidden//4` inhibitory interneurons.
      - Outputs: 2 neurons per behavior (14).
      - Modulators: 2 arousal neurons and 2+2 valence neurons (positive and negative).
    - **Dynamics:** LIF with dt = 1 ms, decay 0.95, threshold 1.0, refractory 2 steps. Inputs are prior-wired to plausible behaviors, as in the spike's `PRIOR`, extended for the new inputs.
    - **`.run(levels: np.ndarray, steps: int = 50) -> None`:** applies pair STDP via traces. Updates accumulate into **eligibility traces** `E_ih`, `E_ho` (decay `ELIG_DECAY = 0.999`/step), plus a small unsupervised component (`A_UNSUP = 0.1 ×` the STDP update applied directly).
    - **`.reward(r: float) -> None`:** `W += LR_REWARD * r * E` for both matrices, clipped to [0, WMAX=1.2]. Then `E *= 0.5`.
    - **Readouts:**
      - `.group_rates -> np.ndarray` (7,), in Hz, EMA.
      - `.arousal -> float` in 0..1.
      - `.valence -> float` in −1..1.
      - `.hidden_rate -> float` in Hz.
    - **`.grow(new_hidden: int) -> None`:** zero-pads existing weights and initializes the new rows and columns with the prior-wiring rule. Existing weights are unchanged.
    - **`.enabled: bool`:** when False, `group_rates` is all zeros. This is the ablation switch.
    - **Visualization buffers:** `.raster() -> np.ndarray` is a bool array (200, n_in+n_hidden+n_out) in chronological order. `.vm_trace() -> np.ndarray` is (200, 4). `.weights_view() -> tuple[np.ndarray,np.ndarray]` returns (W_ih, W_ho).
    - **`.state_dict() -> dict[str,np.ndarray]` / `SNN.from_state(d, seed)`:** used for `.npz` persistence.
  - `HIDDEN_BY_STAGE = {"egg":32,"baby":32,"child":64,"adult":96,"perfect":128,"final":160}` lives in `balance.py`.

### Task 5: Behavior and learning

**Files:**
- Create: `engrama/brain/behavior.py`, `engrama/brain/learning.py`, `tests/brain/test_behavior_learning.py`
- Modify: `engrama/core/balance.py`

**Interfaces:**
- Consumes: `Needs`, `Traits` (Task 2), `SNN.group_rates/arousal/reward` (Task 4), `STAGES` (Task 3).
- Produces:
  - `BEHAVIORS` (same order as Task 4) and `UNLOCK_STAGE = {"show_something":"child"}`. Everything else is unlocked from `baby`, and the egg only does `idle`.
  - `utilities(needs: Needs, traits: Traits, snn_rates: np.ndarray, arousal: float, bandit_q: dict[str,float], stage: str) -> dict[str,float]`:
    - Start from the spike's formulas.
    - `show_something` = curiosidade·criatividade·(1−tedio/200).
    - Add `SNN_WEIGHT (0.6) * clip(rate/40,0,1)` and `BANDIT_WEIGHT (0.5) * q`.
    - Locked behaviors are excluded.
  - `select(utils: dict[str,float], temperature: float, rng: random.Random) -> str` uses softmax sampling. `temperature = 0.05 + 0.15 * traits.norm("curiosidade")`.
  - `context_key(hour: int, user_active: bool) -> str`: hour buckets are night 0–5, morning 6–11, afternoon 12–17 and evening 18–23, giving e.g. `"evening:active"`.
  - `ContextBandit(alpha=0.2)` provides:
    - `.q(ctx) -> dict[str,float]`.
    - `.update(ctx, behavior, r)`.
    - `.to_dict()` / `from_dict`.
  - `Learner(bandit, traits, snn)`: `.reward(kind: str, ctx: str, behavior: str | None, day_index: int) -> None`. It applies the `REWARDS` table below:
    - bandit update (if behavior),
    - `snn.reward(r)`,
    - trait drift.
  - `REWARDS` (in balance) is `{kind: (r, {trait: drift})}`:
    - `"answered_ask": (1.0, {"sociabilidade":+0.5})`
    - `"ignored_ask": (-0.3, {"independencia":+0.3, "sociabilidade":-0.2})`
    - `"shared_project": (0.6, {"curiosidade":+0.5})`
    - `"played_together": (0.8, {})`
    - `"pet": (0.4, {})`
    - `"liked_food": (0.3, {})`
    - `"refused_food": (-0.1, {})`
  - Interrupt budget constants: `ASK_MIN_INTERVAL = 20*60` (sim seconds) and `ASK_ANSWER_WINDOW = 120`.

    - `"sleep_toggle"`.
    - `"rest" {"on": bool, "manual": bool}`: the sim tracks `.rest_manual`, and automatic events never clear a manual rest.
    - `"share" {"topic"}`: reward "shared_project" and `bump_topic`.
    - `"facts" {"facts": [(k,v,conf)], "topics": [(name,delta)], "valence": float}`: from the language worker.
      - Upsert the facts with source "chat" and bump the topics.
      - Set the `chat_pos`/`chat_neg` stimulus for the next tick from the valence.
      - A valence < −0.3 means the user seems sad: `apoio` +30 and an episode with importance 0.6, so the creature wants to comfort them.
  - `.outbox: list[Event]`: things for the UI (`"say"`, `"evolved"`, `"growl"`), drained by the UI each frame via `.drain_outbox()`.

  - `.context() -> str` returns the current `context_key`.
